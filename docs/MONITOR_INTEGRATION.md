# Подключение монитора к шлюзу на эмуляторе мойки

Для того, кто делает монитор (`scada-editor-backend`). Что изменилось, как запустить и что
проверить. Контракт Kafka прежний (топики, тело `{value, quality, timestamp}`, статусы команд) —
изменились **источник данных** и **имена каналов**.

## Что это

Шлюз теперь читает станцию **только по OPC UA**. Данные даёт **эмулятор мойки**: настоящая
прошивка ptusa с проектом станции BN1-МСА1 (без модулей ввода-вывода, логика станции живая).

У прошивки есть собственный OPC UA-сервер, но он отдаёт только `<прибор>.state/.value` — 22 %
каналов, без режимов `M`, уставок, технологических объектов и `SYSTEM`, и запись `state` на
прибор не действует. Поэтому между прошивкой и шлюзом стоит **фасад** (`ptusa-opcua/`) — маленькая
программа-переводчик. Она берёт у прошивки её родным протоколом (driver-master) **всё** и
выставляет как OPC UA-сервер; запись клиента превращает в команду прошивке.

```
прошивка ptusa  ←driver-master→  фасад  ←OPC UA :4840→  шлюз  →Kafka→  монитор
 (проект BN1-МСА1)               (переводчик)
```

Со стороны шлюза и монитора фасад — обычный OPC UA-сервер станции.

## Что изменилось для монитора

| | Было (Python-симулятор) | Стало |
|---|---|---|
| Источник | симулятор, 3 контроллера, 2517 каналов | прошивка ptusa, 1 контроллер, **1834 канала** |
| Имя канала (Kafka-key) | `Барановичи-1.BN1_MCA1.V_ST_1.LINE1V0.ST` | **`Барановичи-1.BN1_MCA1.LINE1.V0.ST`** — объектный путь вашей базы каналов |
| Запись | только команды и уставки | **все числовые каналы** (1816 из 1834), строки — только чтение |
| Обрыв связи | значение замирало | кадр `value=null, quality=BAD` (`GATEWAY_SEND_BAD_FRAMES=true`) |

**Ключи изменились — проекты, привязанные к старым ключам, нужно перепривязать.** Новые ключи
строятся вашим же кодом импорта `.cdbx` (`CdbxParser`, `PlcProjectParser`, `ObjectPathMapper`):
если импортировать `BN1 MCA1 NEW.cdbx` с площадкой `Барановичи-1` и проектом `BN1_MCA1`, дерево
каналов совпадёт с ключами телеметрии.

## Что нужно

- Docker (на Windows — Docker Desktop, Linux-контейнеры), JDK 21.
- **Папка проекта ПЛК** станции (`BN1-CIP1`: `main.plua`, `main.io.lua`, `main.objects.lua`…) **вместе с
  подмодулем `bin/`** (`git submodule update --init` в папке проекта; нужен
  `bin/linux-default/Release/ptusa_main`). Проект проприетарный — в репозиторий шлюза не входит.
- Этот репозиторий (ветка/версия, где есть `ptusa-opcua/` и `config/stations/`).

## Запуск в вашем стенде (docker-compose монитора)

1. Скопируйте `docs/monitor/docker-compose.gateway.yml` из этого репозитория поверх вашего
   `docker-compose.gateway.yml` (симулятор заменён на `scada-ptusa` + `scada-opcua`, шлюз берёт
   `config/stations/BN1_MCA1.yaml`; Kafka, топики и кадры BAD — как у вас).
2. Соберите jar шлюза (как и раньше):
   `cd $SCADA_GATEWAY_PATH/SCADA-gateway && ./mvnw -DskipTests package`
3. Запустите (PowerShell):
   ```powershell
   $env:MOIKA_PROJECT = "C:/путь/к/BN1-CIP1"        # прямые слэши
   $env:SCADA_GATEWAY_PATH = "C:/путь/к/scada-gateway"
   docker compose -f docker-compose.yml -f docker-compose.gateway.yml up -d
   ```

## Запуск, если шлюз у вас на хосте (как в `start-all.ps1`)

В Docker поднимаются только прошивка и фасад; шлюз, Kafka и Postgres — ваши.

```powershell
cd C:/путь/к/scada-gateway
$env:MOIKA_PROJECT = "C:/путь/к/BN1-CIP1"
docker compose -f docker-compose.moika.yml up -d --build ptusa ptusa-opcua      # OPC UA станции: localhost:4840
```

и вместо запуска Python-симулятора запускать шлюз с двумя переменными окружения:

```powershell
$env:CONTROLLERS_CONFIG = "file:C:/путь/к/scada-gateway/config/stations/BN1_MCA1.yaml"
$env:PLC_HOST = "localhost"
# дальше — как у вас: java -jar SCADA-gateway-0.1.0.jar … --gateway.send-bad-frames=true
```

Linux/macOS: `MOIKA_PROJECT=… ./up-moika.sh plc` — то же самое и печатает нужные переменные.
Весь стенд целиком (прошивка + фасад + шлюз + Kafka на :9094 + Postgres): `MOIKA_PROJECT=… ./up-moika.sh`.

Порты: `4840` OPC UA станции, `10100` driver-master прошивки (отладка), `8888` шлюз. Если у вас
ещё запущен Python-симулятор — он занимает `4840`: остановите его.

## Как проверить

- `curl localhost:8888/actuator/health` → `{"status":"UP"}`; в логе шлюза
  `Loaded 1834 tags`, `OPC UA socket up`, `связь установлена`.
- В `scada.tags` — 1834 ключа, все `GOOD`.
- Команда в `scada-commands` `{"commandId":…,"tagName":"Барановичи-1.BN1_MCA1.LINE1.V0.M","value":1}` →
  в `scada-command-results` статус `APPLIED`, и значение возвращается в телеметрию.
- Остановите контейнер `scada-ptusa` — через ~10 с в журнале `DISCONNECTED`, значения приходят
  как `BAD`; запустите — через ~15 с `CONNECTED`.

## Что нужно знать

- Всего в базе каналов 2647 канала: **813 выключены** — их объекта нет в проекте ПЛК (OBJECT4–6,
  сторожевые таймеры со старыми именами, поля, которых у прибора нет). Прошивка их не отдаёт.
- В прошивке есть ещё ~300 значений, которых нет в базе каналов (`ACID_PAR`, `CAUSTIC_PAR`,
  диагностика датчиков…): у них нет имён, под которыми их знает монитор.
- Часть значений (~144: `STATE`, `OPER`, `OPENED/CLOSED`, обороты, токи модулей питания…)
  пересчитывает сама программа ПЛК: запись принимается (`APPLIED`), но значение не «держится».
- `RT_PAR_F[12]` прошивка хранит целым: 7.5 станет 7.
- **Значения датчиков нулевые, графики плоские** — это не ошибка. Эмулятор запущен без ввода-вывода
  (`--no_io`), физического процесса нет; значения — ровно то, что отдаёт прошивка. Живые числа
  появляются, когда их записать (командой из монитора или через `scada-commands` — писать можно
  во все числовые каналы) или когда станция выполняет операцию. Архива в эмулятор не подмешивается.
  На настоящем ПЛК запись в показание датчика перезатрётся сканированием входов.

## Если не запускается

| Симптом | Причина |
|---|---|
| `scada-ptusa` unhealthy, в логе `ptusa_main: not found` | нет подмодуля `bin` в папке проекта: `git submodule update --init` |
| `required variable MOIKA_PROJECT is missing` | не задан `MOIKA_PROJECT` |
| порт `4840`/`8888`/`5433` занят | запущен старый симулятор/шлюз/Postgres |
| шлюз: `нет файла … controllers` / `PLC_HOST` не разрешён | не заданы `CONTROLLERS_CONFIG` и `PLC_HOST` |
| в Docker Desktop проект не монтируется | путь не в списке общих папок; используйте прямые слэши |

Устройство фасада и результаты проверки — `docs/SPECIFICATION.md` §5, `ptusa-opcua/README.md`.
